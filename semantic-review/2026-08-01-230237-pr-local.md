# Question-driven multidimensional reporting with citation-derived coverage

This change replaces the fixed five-category score and mandatory tool sequence with question-driven planning across 13 dimensions, then derives report metadata from cited evidence and execution logs. The runtime citation filter is conservative, all 15 tools currently map to the intended 13 dimensions, C2/C5 payloads are unchanged, and rendering remains local. The main regressions are in degraded-run reporting and tests that can pass evidence-free reports or reject valid prose.

**Watch for:** **confirmed** zero-citation reports pass the live integration gate; **confirmed** one failed tool call can be rendered twice and orchestration failures are mislabeled as dimensions; **confirmed** the raw `/3` assertion rejects unrelated text; **confirmed** exception fallback and complete runtime tool registration are not meaningfully tested.

## High-level view

The report summary counts only IDs that exist in `evidence_list` and appear in model analysis. **confirmed:** the live integration run still accepted two reports with zero cited evidence and zero analyzed dimensions, so the delivery gate does not enforce the evidence-backed behavior it measures.

Failure metadata copies every failed execution-log row. **confirmed:** tool-internal and dispatcher logs become duplicate failed dimensions, while `agent_loop` timeout/error rows become an “unknown dimension” rather than an orchestration limitation.

The runtime prompt no longer mandates a fixed order or five-category score, and the 15-entry dimension mapping is correct. **confirmed:** runtime registry coverage still checks only the original six tools, leaving drift between tool configuration, dispatch, and reporting undetected.

## Evidence-free reports pass the delivery gate

**confirmed — high severity.** `run_single_case` computes `cited_evidence_count` and `analyzed_dimensions`, then only verifies that those same values are printed in the report (`tests/test_local_run.py:117-162`). It never requires a valid citation or any analyzed dimension. The live run demonstrated the impact: the SOL case passed with 7 collected records but 0 cited records/0 dimensions, and the ETH/SOL case passed with 15 collected records but 0 cited records/0 dimensions.

`build_report_metadata` and `build_analysis_summary` correctly prevent uncited or nonexistent IDs from being counted (`lambda/handler.py:86-94`, `lambda/report.py:205-225`). The integration gate should fail when no valid citation remains and verify every key-evidence claim references an existing ID, rather than only comparing rendered count strings.

## One logical failure becomes multiple failed dimensions

**confirmed — medium severity.** `build_report_metadata` appends every execution row in `FAILED_STATUSES`, without deduplication or restricting rows to data tools (`lambda/handler.py:98-116`). `build_analysis_summary` preserves every entry (`lambda/report.py:246-264`), then the renderer labels them “已嘗試但未成功的維度” and injects each into confidence limitations (`lambda/report.py:434-460`).

The live BTC run showed one Polymarket failure twice: once from the tool’s internal log and once from dispatcher logging. A direct check also confirmed identical `get_prediction_market` rows survive and an `agent_loop` timeout becomes `dimension=None`, rendered as an unknown failed dimension. Use one authoritative logging layer or a logical attempt identity for deduplication, and render orchestration failures separately.

The fixtures contain only one failure per tool (`tests/test_handler_agent.py:477-500`). The report test also requires failures in both confidence and appendix but does not cover repeated log rows or failure prose already emitted by the model (`tests/test_report.py:208-227`).

## The fixed-score guard rejects any `/3` text

**confirmed — medium severity.** The integration test treats bare `/3` as a fixed score (`tests/test_local_run.py:168-170`), so dates, ratios, and URLs can fail. The live BTC scenario failed solely on this check, producing a 2/3 suite result despite completing in 100.1 seconds with nine evidence records.

The runtime fixed score is gone: the initial prompt is question-driven (`lambda/agent.py:647-670`), `report.calculate_coverage` was removed, and the appendix emits counts without a denominator. Match score context such as `覆蓋率 ... n/5` or `維度分數 ... n/13` instead of an unqualified fragment.

## Offline rendering fallback is asserted without being exercised

**confirmed — low severity.** `test_render_report_contains_exceptions_and_never_calls_network` monkeypatches `requests`, which `report.py` does not call; `None` inputs stay on normal guarded paths and never exercise the outer fallback (`tests/test_report.py:260-276`). Force `_parse_analysis_sections` or another helper to raise, then assert the fallback retains all three required sections.

## Complete mapping is tested separately from the runtime registry

**confirmed — low severity.** The static test verifies all 15 `TOOL_DIMENSIONS` entries and 13 target dimensions (`tests/test_report.py:56-79`), but the dispatch test checks only the original six names (`tests/test_handler_agent.py:276-284`). Assert the same 15-name set across report mapping, Bedrock tool config, and dispatch so a capability cannot remain mapped but become unusable.

## Delivery readiness audit

1. ❌ **Four deliverables and deployable instructions — confirmed.** `outputs/report.md`, `outputs/evidence_list.json`, `outputs/execution_log.jsonl`, source, and README exist. README is not deploy-as-written: the production frontend retains `https://請填入你的-function-url...`, README does not instruct replacing `API_URL`, and dependency packaging is not reproducibly pinned.
2. ❌ **5 coins × 3 question types and <12 minutes — confirmed.** `tests/test_local_run.py` defines three scenarios (`tests/test_local_run.py:30-56`), not 15. The executed suite was 2/3: 74.8s PASS, 100.1s FAIL, and 98.0s PASS; each run and the 272.9s batch were under 12 minutes.
3. ❌ **Three-sample evidence traceability — confirmed.** Fear & Greed and Google News evidence URLs returned HTTP 200; their references are reproducible and claims map to report judgments. The price record names `baseline/BTCUSDT_daily_ohlcv.csv`, but the repository contains `data/baseline/BTC_daily_ohlcv.csv`, leaving only 2/3 samples directly traceable.
4. ✅ **Report quality.** The inspected report has 市場判斷/關鍵依據/信心說明, at least three source dimensions, explicit contradictions and limitations, and no prohibited recommendation phrase.
5. ✅ **Execution log fields.** The inspected log contains UTC timestamps and tool calls; the live run recorded failures. Failure metadata duplication remains issue 2 above.
6. ❌ **Frontend, downloads, and demo flow — confirmed.** The Function URL is a placeholder, and `scripts/demo_server.py:153-156` returns `#` for both downloads. No deployed site or recording link was available for end-to-end validation.
7. ❌ **Secrets, environment completeness, reproducibility — confirmed.** No obvious committed real credential was found and `.env.example` uses placeholders. `BASELINE_END_DATE` is absent as an environment variable, and `requirements.txt` uses open `>=` ranges.

**Readiness conclusion:** 尚缺 5 項，不可提交。修復優先序：先阻止零引用報告並去除失敗重複/誤分類；再修正 `/3` 誤判並補齊 5×3 矩陣；接著修正 baseline source reference；最後完成部署 URL/下載流程、README、環境變數與依賴鎖定。
