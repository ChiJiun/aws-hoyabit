# 資料來源目錄 — 目標資料、訊號與呈現方式

TA:主動交易者。原則:每個來源都要回答「這能產出什麼**別人沒有的訊號**」,而不是「能抓到什麼資料」。
金鑰與額度需賽前逐一實測(rate limit、免費層範圍),結果回填本表「賽前驗證」欄。

## 二、訊號組合(來源 × 訊號的高價值交叉)

單一來源的數據是資訊,**兩個來源的矛盾才是訊號**:

| 組合訊號 | 需要的來源 | 交易者解讀 |
|---|---|---|
| 資金費率轉負 + 價格持平 | Hyperliquid × price | 空頭擁擠但砸不下去 → 軋空燃料 |
| OI 新高 + 帶寬壓縮(A2) | Hyperliquid/Coinglass × quant | 槓桿堆積 + 波動壓縮 = 大幅變盤前兆 |
| 大規模清算後 + 情緒極恐 + 鏈上活躍度未降 | Coinglass × F&G × onchain | 強制去槓桿完成、基本面完好 → 歷史上常見階段底特徵 |
| Polymarket 事件機率大幅移動 + 現貨未反應 | Polymarket × price | 資訊尚未被現貨市場消化(或預測市場錯了)— 兩種都值得寫 |
| 穩定幣供給增加 + 現貨量縮 | DefiLlama × quant | 彈藥進場但未開火,觀望資金堆積 |
| IV 抬升 + 已實現波動低 | Deribit × quant | 市場在為某個已知事件買保險 → 去找是什麼事件(接 news) |

## 三、呈現方式

### 報告內(Markdown,評分主體)
- 每個訊號 = 一張「訊號卡」:分級(🔴/🟡)+ 一句話標題(讀值 + 為什麼重要)+ 數據(值、百分位、evidence_id)+ 歷史對照 + 限制
- 「⚪ 已檢查、無異常」清單:逐項列出檢查過的訊號與常態讀值 — 展示覆蓋面
- 儀表板式摘要表(報告開頭):五個維度(價格動能/槓桿結構/鏈上/情緒/總經)各給一行狀態 + 方向箭頭,30 秒可讀完
- 數字呈現紀律:永遠「絕對值 + 歷史百分位 + 視窗」,如「資金費率 0.08%/8h(近 90 日第 96 百分位)」

### 前端(Demo 錄影的視覺焦點)
- 執行中:即時顯示工具呼叫時間軸(「✓ Hyperliquid 資金費率 1.2s」),讓評審親眼看到多源蒐集過程
- 結果頁頂部:五維度狀態列(色塊)+ 異常訊號卡片(紅/黃邊框)
- 每張卡片附「查證」摺疊區:展開即見 source URL、fetched_at、引用片段 — 把可回溯性做成看得見的 UI

### Evidence List
- 衍生品/鏈上類證據的 content_reference 必含:endpoint、查詢參數、時間範圍、原始數值 — 評審抽查時可重現

## 四、取捨與範圍控制(15 分鐘預算)

- **必做**(主線):Tier 3 基準層 + Hyperliquid + Coinglass(或 Binance Futures 備援)+ F&G + Google News/媒體 RSS + 對應幣種鏈上 + FRED → 6–7 類來源
- **強烈建議**:Polymarket(創意度)、Deribit(BTC/ETH 限定)、DefiLlama(穩定幣供給)
- **有餘裕才做**:Reddit、LunarCrush、大額轉帳追蹤
- 每個來源一個 collector 函式、都走契約 C1、單源失敗即降級 — 來源多不會增加耦合,只增加覆蓋
- 賽前演練必測:全來源並行抓取總耗時(目標 ≤ 3 分鐘)與各家 rate limit
